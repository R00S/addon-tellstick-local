# Branch: 5fe97fc32425f971ae084741 — 3.3.1.x

## Session — 2026-11-05 — Home Assistant 2026.11 compatibility (RTL-433 EntityCategory)

**Trigger:** home-assistant/core issue #190450 — after 2026.11.0 (HACS replaced by
the built-in Marketplace) a large number of community custom integrations show as
"Not loaded" and cannot be reloaded. Question was whether our end-users are
affected, and to make the integration 2026.11-ready.

### What was investigated

1. Read the issue and the 2026.11 release notes: the failures are per-integration
   `ImportError`s from names that 2026.11 removed from the "wrong" modules (e.g.
   `StateType` from `components.sensor`, `UnitOfTemperature` from
   `components.climate`), mixed with Marketplace migration confusion. Not a
   blanket breakage of everything installed via HACS.
2. Installed a real Home Assistant **2026.11.0** (Python 3.14.7 — 2026.11 requires
   Python >= 3.14.2) plus **2026.10.4** for a baseline, and ran
   `tests/test_ha_integration.py` against both.
3. Probed every Home Assistant symbol the integration imports (22 modules).

### Findings

- The integration itself loads and passes the full test suite on 2026.11.0:
  integration load, user config flow, hassio discovery, OptionsFlow, all platform
  module imports. `DeviceInfo` usage was already the new dataclass-friendly
  keyword form; returning a boolean from `async_entry` methods is still supported
  for custom integrations; `tellduslive` YAML import removal is a different domain.
- **One real break:** `Rtl433Sensor.__init__` imported `EntityCategory` from
  `homeassistant.components.sensor` for the `battery_ok` / `battery_V` fields.
  2026.11 removed that name from the component (it lives in `homeassistant.const`
  on both 2026.10 and 2026.11).
  Impact: with a stored RTL-433 battery/voltage entity, sensor **platform setup
  raised `ImportError`**, taking every `tellstick_local` sensor down (switch/light/
  cover/button platforms unaffected). The live-discovery path also failed on any
  rtl_433 reading containing `battery_ok` (most devices), so no new RTL-433
  entities were created.

### Changes made

- `custom_components/tellstick_local/sensor.py` — `EntityCategory` is now imported
  at module level from `homeassistant.const`; the lazy import inside
  `Rtl433Sensor.__init__` is gone. Mirrored to
  `tellsticklive/rootfs/usr/share/tellstick_local/sensor.py` (files verified
  identical).
- Version bumped: `3.3.1.6` → `3.3.1.7` (both `manifest.json` files).
- `docs/USER_GUIDE.md` — new troubleshooting entry for the RTL-433 symptom
  ("All sensors unavailable after updating Home Assistant (RTL-433)").

### Verification

- `python tests/test_ha_integration.py` → ALL TESTS PASSED on 2026.11.0 **and**
  2026.10.4 (no regression for older HA).
- Sensor platform setup with stored RTL-433 battery + voltage + temperature
  entities on 2026.11.0 → 3 entities created, battery/voltage `diagnostic`.
- Live-discovery construction of `battery_ok`, `battery_V`, `temperature_C`
  entities on 2026.11.0 → all created.
- `compileall` clean; no `components.sensor import EntityCategory` left in the repo.
