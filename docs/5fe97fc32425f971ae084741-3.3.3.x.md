## Session — 2026-11-05 — Home Assistant 2026.11.0 compatibility (3.3.3.0)

**Trigger:** home-assistant/core issue #190450 — after 2026.11.0 (HACS replaced
by the built-in Marketplace) many community custom integrations show as
"Not loaded". The integration was checked against a real 2026.11.0 install and
made 2026.11-ready. Shipped to `main` in 3.3.2.3; this branch re-releases it as
**3.3.3.0** so it is the first release of the 3.3.3 series.

### Findings

- Everything else already worked on 2026.11.0: integration load, user config
  flow, hassio discovery, OptionsFlow and every platform import. `DeviceInfo`
  was already built with keyword arguments (the new dataclass form), returning a
  boolean from config-entry methods is still supported for custom integrations,
  and the `tellduslive` YAML import removal is a different domain.
- **One real break:** `Rtl433Sensor.__init__` imported `EntityCategory` from
  `homeassistant.components.sensor` for the `battery_ok` / `battery_V` fields.
  2026.11 removed that name from the component; it lives in
  `homeassistant.const` on 2026.10 and 2026.11 alike.
  Impact: with a stored RTL-433 battery/voltage entity, sensor **platform setup
  raised `ImportError`**, taking every `tellstick_local` sensor down — switch,
  light, cover and button entities were unaffected. Live discovery also broke on
  any rtl_433 reading containing `battery_ok` (most devices).

### Changes

- `custom_components/tellstick_local/sensor.py` — `EntityCategory` imported at
  module level from `homeassistant.const`; the lazy import inside
  `Rtl433Sensor.__init__` is gone. Mirrored to
  `tellsticklive/rootfs/usr/share/tellstick_local/sensor.py`.
- `docs/USER_GUIDE.md` — troubleshooting entry "All sensors unavailable after
  updating Home Assistant (RTL-433)", now naming **v3.3.3.0** as the fixed
  version.
- Version `3.3.2.3` → **`3.3.3.0`** in both `manifest.json` files (C digit
  bumped, D reset — the series starts fresh on `main`).

### Verification

- `python tests/test_ha_integration.py` → ALL TESTS PASSED on a real Home
  Assistant **2026.11.0** (Python 3.14.7) and on **2026.10.4** (no regression).
- Sensor platform setup with stored RTL-433 battery + voltage + temperature
  entities on 2026.11.0 → 3 entities created; battery/voltage are `diagnostic`.
- `Rtl433Sensor(field="battery_ok")` / `battery_V` / `temperature_C` all
  construct on 2026.11.0.
- Mirror copies byte-identical; no `components.sensor import EntityCategory`
  left in either copy.

### Not verified

- Real hardware (Duo / ZNet + a live rtl_433 MQTT broker): loading, flows and
  entity creation were exercised, RF behaviour was not.

## Confirmation — 2026-11-05 — issue #114 and #115 are intact on `main`

Both Net/ZNet regressions were checked again on the merged `main` (`caf788d`)
rather than trusted to history, because the #114 fix landed *after* the branch
that became #118 was cut:

- **#115** (`8e39b46`, shared UDP listener) — present. `_NetUdpHub` at
  `net_client.py:2760`, source-IP dispatch in `_handle_datagram`, per-host
  `_subscribers` with reference counting, and `last_packet_at` /
  `packets_received` counters used by `debug_connection` ("Last packet
  received", `__init__.py:1138`).
- **#114** (`21c94f9`, ephemeral listener port) — present. The hub binds
  `sock.bind(("", 0))` (`net_client.py:2791`) and the comment at 2786 records
  why: the v1 Net firmware opens its event socket on the registrant's source
  port, so registering from 42314 collides with its own command socket.
  Port 42314 now only appears in the docstring describing the device side.
- `tests/test_net_udp_hub.py` is on `main` and passes; `docs/USER_GUIDE.md` §8
  and the troubleshooting entry for several TellSticks are present.

Nothing was lost in the #118 → #129 transition: the fix commits were ancestors
of the merged branch, and only the two duplicate commits from the abandoned
`freebuff/8aa7ad…` line were dropped (their changes shipped as `b704552` and
`7a58d1c`).
