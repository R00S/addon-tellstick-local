# Branch: 8aa7ad394de32864627ccce6 — 3.3.1.x

## Session — 2026-10-25 — Issue #115 (Net/ZNet: primary + mirrors drop UDP events)

**Trigger:** issue #115 — with several Net/ZNet entries (one primary + mirror
entries), sensor events stop arriving on the primary. Debug logs show one
entry logging 1,200+ "ignoring packet from … (expected …)" lines while every
other entry logs "no packets from … in 70s". Reloading the primary "fixes" it
until the next restart. `debug_connection` reports "Connection: OK" the whole
time. Also reported: `ERROR [homeassistant.core] Unable to remove unknown job
listener` when reloading an entry.

### Root cause

Every config entry created its own `TellStickNetController` with its own UDP
socket bound to port 42314 (all with `SO_REUSEADDR`). A unicast datagram is
delivered to only **one** of those sockets — in practice the one bound last —
so only one entry ever received traffic, and its `_event_loop` dropped every
datagram whose source IP was not its own host. Which entry "wins" depends on
startup/reload order, so the symptom moves around. This also defeated mirror
forwarding: a mirror's socket swallowed the primary's packets (and vice versa).

### Fix applied

1. **Shared UDP listener (`_NetUdpHub` in `net_client.py`)** — all Net/ZNet
   controllers share one socket (still port 42314, ephemeral-port fallback
   preserved). One receive loop dispatches each datagram **by source IP** to
   the controller(s) registered for that host; unknown sources are dropped
   with a debug line. The socket is reference-counted: it opens with the first
   subscriber and closes with the last, so entries can be added/reloaded/
   removed independently. Controllers no longer bind sockets; `connect()`
   subscribes + sends `reglistener`, `disconnect()` releases. Datagrams
   arriving between `connect()` and `start_event_listener()` are buffered and
   flushed (preserving the old kernel-buffering behaviour). Idle "no packets
   from X in 70s (waiting…)" logging is preserved per host in the hub.
2. **`debug_connection` now shows "Last packet received"** per Net/ZNet entry
   (timestamp, age, packet count) so a silently starved entry is visible
   instead of a bare "Connection: OK" (explicitly requested in #115).
3. **Fixed "Unable to remove unknown job listener" on reload** — the
   `EVENT_HOMEASSISTANT_STARTED` one-shot listeners (primary + mirror paths)
   are no longer wrapped in `entry.async_on_unload()`. They remove themselves
   when they fire; removing again at reload logged the error. A leftover
   listener is harmless (`reconnect()` is a no-op on a disconnected controller).
